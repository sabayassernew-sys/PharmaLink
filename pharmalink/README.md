# تحديث 2.2 — إدارة العروض والرادار

## العروض
- الصفحة الافتراضية للعروض المنشورة فقط. تبويبات منفصلة للموقوفة وطلبات الاعتماد وسجل التغييرات.
- لكل عرض معرف ثابت وتوقيت إنشاء وتحديث للأحداث الجديدة. لا تُخترع تواريخ للعروض القديمة؛ تظهر عبارة وقت غير مسجل عند غيابها.
- الإيقاف يمنع الطلبات الجديدة ويحفظ الطلبات القائمة. إعادة النشر من الموقوفة تمر بمراجعة كمية متاحة وسعر ثم معاينة وتأكيد، وتعيد نفس معرف العرض دون صف جديد.
- يمنع إعادة عرض قديم عند وجود عرض نشط بديل لنفس بند المخزون. العرض القديم يبقى في التاريخ ولا يدمج قسرًا مع البديل.
- كمية التعديل تعني الكمية المطلوبة للطلبات الجديدة، وليست إجماليًا بديلًا للمحجوز أو المرسل. يحتفظ النظام بالكميات الملتزم بها والمكتملة، ويعيد حساب الإجمالي. أسعار وقيم الطلبات السابقة لا تتغير.
- وحدة البيع ثابتة إذا كان للعرض تاريخ طلبات. تعديلها يتطلب عرضًا مستقلًا بعد إيقاف العرض السابق؛ لا يُحوّل تاريخ الصفقات.
- المستقل يرى وصفًا خاصًا لإدارة عروضه، وليس وصف الفرع الذي ينتظر الإدارة.

## الرادار
- يعرض عروضًا مطابقة بالاسم، ويستبعد عرض الصيدلية نفسها وعروض سلسلتها والموقوف وغير المؤهل والنافد.
- تفاصيل: الدواء والمادة الفعالة والبائع والتشغيلة والصلاحية ووحدة البيع والكمية المتاحة والسعر.
- فتح التفاصيل لا يخلق طلبًا أو حجزًا. زر منفصل ينقل لمراجعة الشراء؛ التأكيد وحده ينفذ الطلب وفق الصلاحية.
- إدارة السلسلة تستعرض التفاصيل؛ الفرع ينشئ الشراء والإدارة تعتمد.
- لا إشعار خلفي جديد في هذا التحديث؛ المطابقة بالاسم ليست تحققًا صيدلانيًا من بدائل الأدوية.

اختبارات التحديث: 51 اختبار منطق ناجح. النسخة محلية كما سبق؛ لا تغيير في المصادقة أو الدفع الحقيقي. الرجاء تصدير نسخة بيانات احتياطية قبل استبدال ملفات التطبيق.

# تحديث 2.1 — الوحدات والبيع وتنبيهات الموردين

- المستقل ينشر مباشرة بالسعر والكمية. الطلب النشط يظهر مع أدوات تعديله أو سحبه، ولا يعرض نموذجًا مكررًا بصمت.
- من تفاصيل الصنف: تعريف العبوة ومحتواها وتفعيل التجزئة اختياريًا. الرصيد الحالي يُعتبر عبوات خارجية ويُحوّل مرة واحدة إلى الوحدات الداخلية. لا تحول رصيدًا محسوبًا أصلًا بالوحدات الداخلية. يمنع التحويل عند وجود تاريخ طلبات أو إعلانات نشطة.
- عند تعريف كل باكت = 10 شرائط: الموجود 3 باكتات يصبح 30 شريطًا. يمكنك نشر 3 باكتات كاملة أو 30 شريطًا إذا سمحت بالتجزئة. وحدة البيع وسعرها يظهران للمشتري. اختيار المشتري لا يغير الوحدة التي اختارها البائع.
- عرض بوحدة واحدة متاحة: كمية ثابتة مع سعر إجمالي؛ أكثر من وحدة: عدد صحيح ضمن المتاح مع إجمالي محسوب.
- الحجوزات والإرسال والاستلام تحسب بالوحدة الأساسية نفسها. الصفقات تحتفظ بسعرها، ولا يسمح بتعديل العرض المرتبط بطلبات قائمة؛ يمكنك سحبه دون إلغاء تلك الطلبات.
- إعداد مدة تنبيه المورد الافتراضية من الإعدادات، وتخصيصها من تفاصيل الصنف. تنبيهات قبل المهلة ويومها وبعدها في لوحة التحكم والجرس، تفتح تفاصيل البند. تحديث الصفحة يعيد حساب التنبيهات حسب اليوم؛ هذه ليست خدمة إشعارات خلفية عند إغلاق التطبيق.
- حالات مرتجع المورد: متابعة مفتوحة، تم الإرجاع، رفض المورد، غير قابل للإرجاع. تمديد الموعد بتعديل التاريخ. إغلاق التذكير لا يغير الرصيد؛ يسجل الخروج الفعلي بتسوية موثقة.
- لوحة المستقل تعرض طلباته الخارجية وعروضه بدل مؤشرات المناقلات الداخلية.
- قالب CSV فارغ فعلًا؛ مثال البيانات في public/example-inventory.csv منفصل.
- بعد تعريف العبوة يجب استيراد نفس التشغيلة بوحدتها الأساسية وسعر الوحدة الأساسية، ويرفض النظام إدخالها بوحدة مختلفة لتجنب تكرار الرصيد.
- لم تُغير شروط أهلية الأدوية (30 يومًا والمبردات) في هذا التحديث؛ تظل قيود النسخة المحلية الموثقة.

التشغيل كما في الإصدار السابق. افتح المجلد الجديد مستقلًا. على عنوان المتصفح نفسه تستمر البيانات القديمة من التخزين المحلي؛ انسخها احتياطيًا قبل أي تجربة تحويل. لا تمسح بيانات النسخة السابقة تلقائيًا.

# PharmaLink — فارما لينك
نسخة محلية أعيد بناؤها باستخدام React + TypeScript + Tailwind CSS + Vite.

## التشغيل الأسهل على Windows
1. فك ضغط الملف كاملًا داخل مجلد جديد، ولا تستبدل مشروعك الأصلي مباشرة.
2. ثبّت Node.js 22.12 أو أحدث إذا لم يكن موجودًا.
3. افتح START.bat؛ يفتح المتصفح على http://127.0.0.1:3000.
4. أبقِ نافذة التشغيل مفتوحة. إغلاقها يوقف الخادم فقط ولا يمسح البيانات المحفوظة.

START.bat يشغّل نسخة dist الجاهزة، ولا يتطلب npm install أو اتصال إنترنت للمعاينة. لا تفتح index.html بالنقر المباشر لأن الوحدات تحتاج خادم HTTP.

## تعديل الكود في أنتيقرافتي
افتح مجلد pharmalink ثم شغّل:
```sh
npm ci
npm run dev
```
افتح العنوان الذي يعرضه الطرفية. أوامر الفحص:
```sh
npm test
npm run typecheck
npm run build
```
بعد تعديل المصدر نفّذ npm run build لتحديث النسخة التي يشغلها START.bat. استخدم عنوانًا ومنفذًا ثابتين؛ التخزين المحلي منفصل لكل عنوان/منفذ ومتصفح.

## الحسابات التجريبية
بدّل الحساب من الشريط العلوي. يوجد فرع حدة والسبعين وشعوب، وإدارة السلسلة، وصيدليتان مستقلتان، ومدير منصة، وزائر، وحساب قيد المراجعة.
هذا تبديل لاختبار الأدوار وليس نظام كلمات مرور أو مصادقة آمنًا. قيد الحساب غير الموثق يمنع تشغيل وظائفه إلى حين اعتماد الإدارة.

## ما تغير
- استبدال ملفات HTML وJavaScript المتشابكة بصفحات ومكونات React مكتوبة بصرامة TypeScript.
- ألوان الهوية: #073B59 و#00ADB5 وخلفية #F4F7FA، وقائمة جانبية يمينية قابلة للطي وتصميم متجاوب.
- الاحتفاظ بالهوية الأصلية في public/brand/identity.png وعرضها بصفحة الهوية. رمز الواجهة المتجهي تفسير مبسط للترابط وليس استبدالًا لملف الهوية الأصلي.
- مصدر واحد للأرصدة والحجوزات والعمليات، مع حفظ localStorage وبث تغييرات النوافذ، وWeb Locks حين يتوفر.
- المعاملة تعمل على نسخة بيانات وتُحفظ بعد نجاح التحقق الكامل؛ الفشل لا يترك خصمًا جزئيًا.
- فصل صفحات المخزون والتداول الداخلي والخارجي. جدول المخزون لا يطلب حالات تداول من ملف Excel.
- استيراد XLSX/CSV فعلي، والتحقق من الأعمدة والتواريخ والكمية والوحدة، ومعاينة الفروق، وتعليق المتعارض، ومنع تكرار دفعة الملف نفسه.
- لا حذف نهائي للتاريخ. تسويات الرصيد مباشرة وموثقة مع منع النزول تحت المحجوز.
- نشر الفائض لا يحجز؛ تخصيص المرسل يحجز؛ الإرسال يخصم ويستهلك الحجز؛ الاستلام يضيف المقبول فقط ويعزل المرفوض.
- منع الاستلام الفارغ أو المكرر أو السالب، ومعالجة الاختلاف والمرتجع بخطوات منفصلة.
- بيانات السائق والتوصيل وتكلفتها غير موجودة في مسارات المشروع الجديد.
- محفظة وعمليات تداول خارجية تجريبية، واعتماد شراء الفرع مركزيًا، ونزاع خارجي وتسوية تجريبية لقيمة المقبول.
- مهلة إرجاع المورد تدخل يدويًا من تفاصيل الصنف، وتظهر تنبيهات قربها؛ لا تُستنتج من صلاحية الدواء.
- سجل عمليات وتقارير ورادار بحث عن عروض مطابقة، وتصدير مخزون ونسخة JSON احتياطية.

## بنية المصدر
- src/domain/types.ts: نماذج البيانات.
- src/domain/access.ts: نطاق الرؤية والتنقل وحساب المتاح والأهلية.
- src/domain/engine.ts: الأوامر وقواعد العمليات والحجز والاعتماد والتسوية.
- src/data/repository.ts: عقد مستودع البيانات والتنفيذ المحلي، لاستبداله لاحقًا بربط خادم.
- src/data/importer.ts: قراءة الملفات الفعلية.
- src/data/seed.ts وlegacy.json: تهيئة بيانات تجريبية مستخرجة من المشروع الأصلي. العمليات القديمة المتعارضة لا يعاد تشغيلها.
- src/pages: الشاشات حسب الوظيفة.
- src/components: عناصر واجهة مشتركة.
- tests: اختبارات منطق العمليات الحقيقية.
- reference/original-project.zip: نسخة المشروع السابق للرجوع فقط، لا تُحمّل أو تُنفذ مع التطبيق الجديد.

اقرئي docs/PERMISSIONS.md لتفاصيل كل دور، وdocs/TESTING.md للتجارب والحدود.

## حدود النسخة الحالية
- محلية لجهاز ومتصفح واحد، ولا تمثل حماية بين مستخدمين موثوقين على خادم. يمكن لمالك الجهاز تعديل التخزين عبر أدوات المتصفح.
- لا ربط Supabase أو تحقق رسمي من تراخيص أو رفع مستندات ترخيص إلى خادم.
- لا تحويلات مالية حقيقية ولا ضمان مالي فعلي ولا تكامل مع بنك أو محفظة.
- محاكاة النزاع الخارجي تسوي المقبول المؤكد وترد قيمة الباقي، ولا تدير النقل أو ترجع مخزونًا غير مستلم تلقائيًا. المرتجع التفصيلي المنفذ في هذه النسخة يخص المناقلات الداخلية.
- الأدوية المبردة والموقوفة والأقل من 30 يومًا متبقية تُتابع بالمخزون وتُمنع من التداول في هذه النسخة.
- إشعارات داخل التطبيق فقط؛ لا رسائل بريد أو واتساب أو إشعارات خلفية أو تنبيه صوتي.
- لا API لأونكس/يمن سوفت ولا تعديل تلقائي لأرصدتهما. ملف الاستيراد ليس دليل جرد فعلي دون مراجعة المستخدم.
- النسخة الاحتياطية تُصدّر كـJSON؛ استعادتها تلقائيًا غير متاحة من الواجهة بعد. لا تمسحي التخزين قبل حفظها.
- ملف SQL السابق داخل الأرشيف المرجعي غير معتمد للنسخة الجديدة. عند الربط تُصمم مصادقة وRLS ومعاملات خادم وتُختبر من جديد؛ لا تنقل الثقة بكائن مستخدم من المتصفح للخادم.
